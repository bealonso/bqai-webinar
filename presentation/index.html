Keyword vs. Semantic Search

Traditional Keyword Search
  • ❌ Matches exact characters and string patterns.
  • ❌ Fails to identify synonyms, intent, or context.
  • ❌ E.g., searching "summer tops" misses "swimming suits" or "beach wear".
Semantic Vector Search
  • ✅ Understands overall context and meaning.
  • ✅ Encodes queries into high-dimensional dense spaces.
  • ✅ Delivers relevant, related results regardless of literal keywords.

How Vector Search Works

1
Encode
Convert unstructured media (text, images, audio) into mathematical vectors using Embedding Models.
2
Index
Organize vectors in a high-performance search space to enable lightning-fast nearest neighbor lookups.
3
Search
Execute similarity queries on the vector index to return semantically closest objects.

Session 02

Embeddings

Turning unstructured media into dense, mathematically computable representations.

Embeddings & Representation Slide 10 of 26

The Challenge of Representation

  • Representing Semantics: How to transform human vocabulary into quantitative measurements while keeping contextual meaning intact.
  • Dense Compatibility: Compiling information into structures suitable for machine learning models without computational waste.
Embedding Scope
Embedding models are highly versatile. While text is standard, they encode images, audio, video, and even computer code into unified mathematical coordinates.
Embeddings & Representation Slide 11 of 26

One-Hot Encoding

  • The Technique: Map every word to its distinct place in a huge, zero-filled vector.
  • Extreme Sparsity: For a 20,000+ vocabulary, 99.99% of cells are zeros, causing high resource waste and model overfitting.
  • No Context: Every vector is orthogonal; the model has no way to know "dog" and "chase" are semantically related.
# Sentence: "dog chase person"
# Vocabulary: [dog, chase, person, my, cat, run]
dog: [1, 0, 0, 0, 0, 0]
chase: [0, 1, 0, 0, 0, 0]
person: [0, 0, 1, 0, 0, 0]

Dense vs. Sparse Embeddings

Sparse Embeddings

Dimensions: Extremely high (e.g. 20,000+ matching vocabulary size).

Values: Almost entirely zeros.

Semantics: Does not convey similarities or meaning relationships between words.

Dense Embeddings

Dimensions: Compact and compressed (usually 768 to 3072).

Values: Floating-point numbers in all dimensions.

Semantics: Rich semantic associations; similar concepts group closely together.

Session 03

Retrieval Augmented Generation (RAG)

Combining high-performance vector searches with generative AI models to prevent hallucinations.

Retrieval Augmented Generation Slide 16 of 26

The Grounding Problem

  • Frozen Pre-training: Standalone Large Language Models (LLMs) only know information up to their last training cutoff.
  • Information Gap: They lack access to corporate internal roadmaps, specific user files, or real-time API data.
  • AI Hallucination: LLMs confidently present incorrect or completely fabricated data due to a lack of facts.
Why Standalone LLMs Fail
They are incapable of requesting missing context, cannot natively verify their training sources, and assume that user prompt assertions are always true.
Retrieval Augmented Generation Slide 17 of 26

Solutions to Hallucination

Fine-Tuning
Retraining models with new specific data. Highly customized, but computationally expensive and requires continuous manual pipeline management.
Prompt Engineering
Carefully shaping standard prompt instructions. Easy to implement, but limited by context window sizes and does not scale cleanly across complex files.
RAG + Vector Search (Highly Recommended)
Leverages high-performance Vector Search to extract exact factual contexts in real-time and inject them straight into the prompt template. Scalable, secure, and extremely cost-effective.
Retrieval Augmented Generation Slide 18 of 26

The "Open-Book Exam" Analogy

  • Closed-Book (Without RAG): The model relies solely on memorized facts from initial training, guessing when uncertain.
  • Open-Book (With RAG): The system queries a reliable textbook/library (Vector Database) in real-time to locate precise reference paragraphs before formulating its response.
  • Vector Search's Role: Serves as the super-fast librarian, extracting the most relevant information in milliseconds.

RAG Technical Architecture

The RAG Pipeline

  • Ingestion: Convert PDF/docs to dense embeddings and insert them into a high-performance index.
  • Query Routing: Encode user query $\rightarrow$ execute K-Nearest Neighbors (KNN) on the vector database.
  • Synthesis: Ground the prompt by appending the retrieved paragraphs and pass it to the Gemini LLM.
User Query: "Current travel alert?"
1. Search Vector Index: k=1
2. Found Paragraph: "US Embassy alert for Italy on May 25..."
3. Grounded Prompt:
"Answer query using this reference context: [...]"
4. Gemini Output: "According to the alert on May 25..."

Session 04

Hybrid Search

Blending the contextual understanding of dense vectors with the precise matching of sparse tokens.

Hybrid Search Optimization Slide 21 of 26

Why Hybrid is Crucial

Dense / Semantic Search

💡 Captures overall user intent, concepts, and synonymous relationships.

❌ Fails on exact numbers, custom product IDs, new SKUs, barcodes, or brand new names outside the training dataset.

Sparse / Token-Based Search

💡 Captures exact keyword alignments and out-of-domain words perfectly.

❌ Lacks conceptual understanding; missing synonyms completely (e.g. ignores "youth" if searching for "kids").

Hybrid Search Optimization Slide 22 of 26

Keyword Vector Mechanics

  • Token-Based Extraction: Break raw texts down into discrete tokens, counting and mapping occurrence frequencies.
  • TF-IDF Weighting: Assesses a word's importance relative to the collection, prioritizing rare words and discounting common conjunctions.
  • Organizing Space: Create a high-dimensional sparse space where documents with similar keyword footprints align closely.
Term Frequency Inverse Document Frequency
TF-IDF balances local term occurrences against overall corpus frequencies to elevate the most unique descriptive search parameters.
Hybrid Search Optimization Slide 23 of 26

Reciprocal Rank Fusion (RRF)

  • The Fusion Challenge: Merging separate rank outputs from keyword and semantic engines cleanly.
  • The RRF Algorithm: Evaluates the reciprocal of each object's rank ($1 / \text{rank}$) across the separate lists.
  • Optimal Prioritization: Promotes items that rank consistently well in both systems, or show an exceptional high score in one.
# RRF Scoring Formula
Score(d) = Σm ∈ M 1 / (k + rm(d))
Where k is a constant (e.g., 60) and rm is the rank in list m.
Hybrid Search Optimization Slide 24 of 26

Vertex AI Hybrid Search

  • Streamlined Operations: Vertex AI Abstracts database complexities, merging dense and sparse indices into one simple endpoint.
  • Code workflow:
    1. Compute TF-IDF sparse vector.
    2. Get Gemini dense vector.
    3. Package into a single Hybrid Query object.
# 1. Build Hybrid Search Query
query = aiplatform.VectorSearchEndpoint.HybridQuery(
dense_embedding=dense_vector,
sparse_embedding=sparse_vector,
rrf_k=60
)
# 2. Call Unified Endpoint
response = endpoint.hybrid_search([query])

Interpreting Hybrid Results

  • Top Results: Align on both keyword and semantic indices (e.g. *"Google Blue Kids Sunglasses"*).
  • Semantic-Only Fits: Rank highly even without precise keyword matching (e.g., *"Google White Classic Youth Tee"* matches "kids" conceptually).
  • Broad Success: Merges precision lookup speed with contextual understanding.
